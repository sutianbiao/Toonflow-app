## 5173 访问不了的真正根因（重要）
排查中发现：
- 单独 `bun run dev:web`（vite --host）能正常起、5173 监听正常；单独起 server 也正常；只有根目录 `bun run dev`（`bun run --filter '@toonflow/web' --filter '@toonflow/server' dev` 双 filter 并发）时 vite 起不来、5173 无监听。
- 结论：当前环境（WSL2 镜像网络 + bun 1.4.3）下，bun 的「同时起两个包」并发 filter 模式会把 vite 搞挂，与代理无关（已验证 unset 代理仍失败）。
- 已修：`package.json` 的 `dev` 脚本改为 `bun run --cwd apps/server dev & bun run --cwd apps/web dev`（server 后台 + web 前台），绕开并发坑。注意 Ctrl+C 只杀 web，需 `pkill -f 'src/index.ts'; pkill -f vite` 收尾，或用两个终端分别 `bun run dev:web` / `bun run dev:server`。
- 浏览器侧务必保持 Windows「系统代理」关闭，否则 localhost:5173 会被送进 127.0.0.1:7892 代理而拒绝连接（3000 能开是因为那次恰巧关了代理）。
